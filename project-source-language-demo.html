三次迭代（8月）

点标签切换 · 看准确率怎么爬上来

第一次：圈数据集 + 摸底

圈选评测数据集，对源语言模型能力做首次系统摸底。

  • 语种合集判断准确率仅 70.8%
  • 40% 样本误检出不存在的小语种
  • 误检 TOP3 占总量 80%：
马来语 ×38西班牙语 ×29法语 ×23

其次是中日混淆：20 条把日语判成中文，推测因中日字符重叠。

本轮关键指标

语种合集准确率70.8%
误检样本占比40%
最大问题：小语种误检 + 中日字符混淆

第二次：口径 + 标准 + 扩语种

  • 占比口径从词数改为字符数，更贴合视觉上的混杂感受
  • 评测标准定为主导语种 / 语种合集 / 语种占比三维
  • 为后续扩语种加入东南亚小语种，共 16 种语言

主导语种 97%、合集 80%、占比（5% 误差阈值）70%。最大问题变成相似拉丁语种混淆——英语被误检为马来语、西班牙语、法语等。

本轮关键指标

主导语种97%
语种合集80%
语种占比70%
合集准确率提升，但暴露拉丁语系误检

第三次：优化拉丁语系检测

核心改动：提高英语在检测中的置信度——在不确定的独立短词/短语与 hashtag 中，更倾向判为英语。

结果大幅跃升：主导语种 100%、语种合集 96%，达到可用标准。

代价可控：少部分法语/马来语短语被判成英语，但两语种相似度确实极高，看 case 属可接受误判。

本轮关键指标

主导语种100%
语种合集96%
合集 70.8% → 96% ✅ 可接受的 trade-off

DECISION 01 · 结论

选 B · 单语种

新模型对小语种判断能力明显更强，旧模型小语种错误率高。旧逻辑唯一优势是"中文/日文字符权重高"的消歧，但不足以抵消整体差距。
DECISION 02 · 阈值

短文本降级阈值定多少？

50 字符：覆盖 40% 笔记 / 80% 评论

75 字符：覆盖 70% 笔记 / 90% 评论
↻ 点击翻面看决策
DECISION 02 · 结论

选 50

50 已能筛掉大部分"不应识别为含小语种"的噪声，减少中译中；75 保护更多但降级影响太大（70% 笔记 / 90% 评论被降级）。
04

两次线上问题治理

从客诉到修复

短文本误翻（9.10–9.11）

现象：中文笔记/评论大量出现翻译按钮，引发客诉。如"我拿到了 offer"因英文超 5% 被判中英混杂。

原因：① 按"某语种占比 >5% 即送翻"；② 中译中用了未训练的开源模型，幻觉输出英文。

解法：SDK 临时回滚止损 → 重调中文 prompt（原样输出），15000 条验证正常率 50%→99.99% → V4 短文本降级（<50 字符只输出主导语言）。

中文笔记降级（9.14–9.15）

现象：带英文话题（#iPhone #MacBook #UI #pku）的中文笔记被判中英混合，对中文用户露出翻译按钮。

原因：英文 tag 多为品牌专名/缩写，虽符合">50 字符且英文 >5%"规则，但产品判断不该出按钮，且量级大、逐个修不完。

解法：生产侧先用 V1 判中文→翻英语+小语种，非中文再走 V2；消费侧读取时先读 V1、再读 V2。
