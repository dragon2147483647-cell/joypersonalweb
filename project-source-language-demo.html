源语言识别模型评测

让模型回答“这条笔记里有哪些语言、各占多少”，支撑“送哪些语种去翻译、以哪个语种为主”的翻译策略。准确率从 70.8% 提高到 96%，并处理了短文本与中文笔记的线上误翻问题。

项目背景

BEFORE · 迭代前

只能判断"混没混"

  • 只输出是否存在混杂
  • 混杂时统一吐出 mix
  • 无法回答：有哪几种语言？各占多少？

AFTER · 目标

细粒度源语言识别

  • 语种集合：文本中全部主要语种
  • 各语种占比：供产品定"占比低于多少不翻"
  • 支撑主动翻译上线与自动翻译扩语种

三次迭代（8月）

第一次：圈数据集 + 摸底

圈选评测数据集，对源语言模型能力做首次系统摸底。

  • 语种合集判断准确率仅 70.8%
  • 40% 样本误检出不存在的小语种
  • 误检 TOP3 占总量 80%：
马来语 ×38西班牙语 ×29法语 ×23

其次是中日混淆：20 条把日语判成中文，推测因中日字符重叠。

本轮关键指标

语种合集准确率70.8%
误检样本占比40%
最大问题：小语种误检 + 中日字符混淆

第二次：口径 + 标准 + 扩语种

  • 占比口径从词数改为字符数，更贴合视觉上的混杂感受
  • 评测标准定为主导语种 / 语种合集 / 语种占比三维
  • 为后续扩语种加入东南亚小语种，共 16 种语言

主导语种 97%、合集 80%、占比（5% 误差阈值）70%。最大问题变成相似拉丁语种混淆——英语被误检为马来语、西班牙语、法语等。

本轮关键指标

主导语种97%
语种合集80%
语种占比70%
合集准确率提升，但暴露拉丁语系误检

第三次：优化拉丁语系检测

核心改动：提高英语在检测中的置信度——在不确定的独立短词/短语与 hashtag 中，更倾向判为英语。

结果大幅跃升：主导语种 100%、语种合集 96%，达到可用标准。

代价可控：少部分法语/马来语短语被判成英语，但两语种相似度确实极高，看 case 属可接受误判。

本轮关键指标

主导语种100%
语种合集96%
合集 70.8% → 96% ✅ 可接受的 trade-off

04

两次回滚（9月）

短文本降级 9.9 – 9.10

问题：短标题、评论的上下文极少。仅凭字符占比，offer、intake、mac、Hip、Airplane 等少量拉丁文本就容易超过 5% 阈值，被判为中英或中小语种混杂；若直接送翻，中文用户会看到不应出现的翻译按钮。

解法：SDK 临时回滚止损 → 重调中文 prompt（原样输出），15000 条验证正常率 50%→99.99%；V4 引入短文本降级：对字符数<阈值的文本，直接降级为单语种结果（取新模型语种列表里占比最大的那一个），不再输出多语种列表。

方案收益：压制短文本中因少量外语 token 导致的误出翻译按钮。实际代价：短文本里的真实双语表达、小语种正文也被压缩为单语种。50 字符阈值约覆盖 45% 笔记、90% 评论。

DECISION 01 · 结论

选 B · 单语种

新模型对小语种判断能力明显更强，旧模型小语种错误率高。旧逻辑唯一优势是"中文/日文字符权重高"的消歧，但不足以抵消整体差距。
DECISION 02 · 阈值

短文本降级阈值定多少？

50 字符：覆盖 40% 笔记 / 80% 评论

75 字符：覆盖 70% 笔记 / 90% 评论
↻ 点击翻面看决策
DECISION 02 · 结论

选 50

50 已能筛掉大部分"不应识别为含小语种"的噪声，减少中译中；75 保护更多但降级影响太大（70% 笔记 / 90% 评论被降级）。

中文笔记降级 9.14 – 9.15

问题：短文本保护后，长中文笔记仍会因 #iPhone、#MacBook、#UI、#pku、#Apple 等英文 tag 被判为中英混合。

解法：旧模型为 V1，新模型为 V2；当前生产与消费链路先由 V1 判断是否为中文——判为中文则翻译为英语和小语种，非中文再使用 V2 判定语言合集，输出多语种结果。

方案收益：减少中文笔记因英文 tag 出现翻译按钮。实际代价：中文内容中的真实外语正文、可翻译外文 tag 一并被降级。说明：本质上是在翻译入口处回避模型判断，不是在判断层消除"外语是否应翻"的歧义。

💡 产品侧判断，这种降级和回滚只能是暂时的策略：为了保护中文用户体验，牺牲了小语种用户体验。后续还需要源语言模型针对「短文本」「话题标签」「源语言中文」这三种情况继续优化。
